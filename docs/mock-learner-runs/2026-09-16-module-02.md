**Date:** 2026-09-16
**Two personas:** Denise (diligent), Marcus (scripted-flaw). Both given only `MODULE-README.md` and a fresh copy of `workshop-folder/`, isolated by construction (not instruction) in a scratch directory containing nothing else — no other module, no maintainer docs.

## Process note: adapted for Wade In's deterministic-checker design

Unlike `copilot-fluent` (this Gremlin's origin project), Wade In has no separate hidden AI-graded rubric to reveal after a self-check turn — its Tier 1 checker (`checks/check.sh`) *is* the real, full gate, and the module's own "Required to advance" instructions already tell the learner to run it themselves. So this run skips the copilot-fluent-style "self-check reveal" turn (there is nothing further to reveal) and goes straight from Attempt Agent to an independent Verification Agent, whose job for Wade In is: re-run the same checker independently to confirm reproducibility, and apply human-like judgment to answers.txt's genuineness and the summary's actual fidelity to source — judgment calls beyond what the mechanical check covers.

## A real Gremlin-mechanism boundary, found by running this for real

Module 02's actual teaching moment is watching a live, interactive permission prompt and choosing to approve it (`claude --permission-mode default`). A subagent Attempt Agent has no way to hold up a live interactive approval dialog, so both personas used `claude -p "..." --permission-mode acceptEdits` instead — a real, honestly-disclosed adaptation, not a fabricated interactive session. Both personas' own `PERMISSION_PROMPT` answers disclosed this plainly rather than fabricating a prompt-and-click they never experienced. **Practical implication:** this Gremlin, as currently run, cannot validate whether Module 02's actual interactive teaching moment works — only whether the artifact-producing and verify-yourself halves of the module do. This mirrors Design Principle 2's own named fidelity boundary (simulated artifacts only) in a new, Wade-In-specific way: any module built around a live interactive UI moment (not just Module 02 - Modules 03, 04, 09, 10 all launch interactive sessions too) has this same untested seam. Worth a real human pilot specifically to close this gap, not something this Gremlin's mechanism can close on its own.

## What this run establishes

The gate discriminates correctly: a genuinely diligent attempt passes, and the exact realistic mistake the module's own text names (vague phrasing → flowing prose instead of separate lines) is caught cleanly, on real content produced by a real nested Claude Code invocation, not a hand-constructed test file. No false positive or false negative in either the checker's own verdict or the independent Verification Agent's re-derivation of it. The one real limitation is the process-fidelity gap named above, not a defect in the module or checker.

## Honest limit

Per this Gremlin's own Design Principle 6: a clean run here is evidence the gate is mechanically satisfiable and discriminating against one simulated attempt pair, using a real nested Claude Code CLI to produce the artifact - not evidence a real human, watching a real interactive permission prompt for the first time, will have the same experience. That specific gap is named above, not glossed over.
