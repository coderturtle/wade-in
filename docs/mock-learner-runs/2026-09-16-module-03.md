## Marcus (scripted-flaw) — PASS 6/6, but the scripted flaw didn't actually land

**Scripted flaw:** omit the module's explicit "leave every other line completely untouched" instruction when asking for the correction, on the theory (named directly in the module's own text) that a looser request risks an unrequested collateral edit elsewhere in the file.

**What actually happened:** the real nested `claude -p` invocation, even without that explicit constraint, made exactly the four named corrections and nothing else - confirmed by `diff -u` and a byte-level `cmp -l` pass in Marcus's own transcript, and independently reconfirmed by the orchestrator. The scripted flaw did not produce a flawed attempt this run.

**This is a real, useful finding in its own right, not a wasted run.** It matches this Gremlin's own previously-documented risk (`~/hekton/gremlins/coaching/mock-learner-gremlin.md` Risks: "an agent persona does not reliably simulate carelessness... a bounded comparison task is exactly the kind of thing a language model does competently regardless of the personality framing wrapped around it"). A scripted flaw that depends on the *underlying model taking bait* when instructions are loosened is a fundamentally less reliable discrimination test than a scripted flaw baked directly into the persona's own literal input (like Module 02's line-count flaw, which worked because the persona's own request was verifiably looser, not because it hoped the model would misbehave). Evidence of gate *robustness* against loose phrasing, not evidence the gate would catch a genuine collateral edit.

**Closing the resulting gap directly:** since the scripted persona didn't produce a real collateral edit to test the checker's own "no other line changed" claim against, the orchestrator hand-constructed one directly - took a correctly-corrected file, added one untouched-line edit (reformatted spacing on Johnny Utah's line, an actual realistic "AI cleaned up formatting" failure mode), and re-ran the real checker:

```
FAIL: staff-list-corrected.txt has all 4 corrections applied, with no other line changed
RESULT: FAIL (5/6)
```

Confirmed: the collateral-edit detection genuinely works when a real collateral edit is present. The checker's own claim holds; this particular scripted-flaw persona design just isn't the mechanism that proves it.

Marcus's own answers.txt was judged genuine (specific house rule tied to the actual memo-citation convention, specific verification method named) despite the flaw not landing - not filler, and his self-check honestly named the real gap in his own process (sampled two untouched lines rather than a full diff) rather than claiming false certainty.

## What this run establishes

- The core correction mechanism and the `CLAUDE.md` house-rules mechanism both hold up against a genuine diligent attempt, using real nested Claude Code invocations, not hand-constructed test files.
- The checker's collateral-edit detection is real and works - confirmed via direct construction, not just trusted from its own comment.
- A genuinely useful methodological finding for future scripted-flaw design in this workshop: a flaw that depends on omitting an instruction and hoping the model misbehaves is unreliable; a flaw baked directly into the persona's own literal, verifiable input (wrong phrasing, wrong assumption stated outright) is the more dependable pattern - matches Module 02's working design, worth carrying into remaining modules' scripted-flaw specs.
