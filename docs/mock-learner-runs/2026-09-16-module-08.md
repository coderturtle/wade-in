## Marcus (scripted-flaw) — the flaw didn't land, a real and now-recurring finding

**Scripted flaw:** a literal transcription error baked into his own input - when pasting the letter template into his request, Marcus mistyped `{{amount_due}}` where the real placeholder should have been `{{amount}}`, not matching the CSV's actual `amount` column.

**What happened:** the real nested Claude Code session noticed the CSV had no `amount_due` column, recognized `amount` as the evident intended match, and filled `{{amount_due}}` with the `amount` column's real value anyway - semantic matching rather than literal, unforced, unprompted. All six letters came out fully correct. Marcus's own submission passed `RESULT: PASS (9/9)`, identical to Denise's clean run, and he never learned he'd made a transcription error at all.

**This is the second time in this sweep a scripted flaw has failed to produce a failure because the real model self-corrected a well-specified task's input imperfection** (the first was Module 03's collateral-edit-avoidance). Read together, these two results point at a genuine, recurring pattern worth naming explicitly for this workshop: **a bounded, clearly-specified task (fix these 4 things and leave the rest, fill these 3 fields per row) is something real Claude Code tends to execute robustly even against small, realistic input mistakes** - typos, omitted qualifiers, mismatched field names - rather than propagating them into wrong output. This is genuinely good news about the underlying product's reliability for exactly the kind of small, well-scoped tasks this workshop teaches, but it also means **scripted-flaw personas that rely on the model mishandling an imperfect-but-recoverable instruction are not a reliable way to test this workshop's checkers** - the checker's own discriminating power has to be confirmed some other way (as done for Module 03, by hand-constructing the failure state directly) when a flaw of this shape doesn't land. This module's own placeholder-detection mechanism (`grep -c '{'`) was independently built, fixed, and directly confirmed working during Module 10's DDD process earlier this same session, so it isn't re-verified from scratch here - but the general lesson (design scripted flaws around facts a real, competent model attempt genuinely cannot recover, like Module 02's line-count shape or Module 07's backwards-stated rule, not around omissions or typos a good model will likely absorb) is the most useful thing this run produced.
