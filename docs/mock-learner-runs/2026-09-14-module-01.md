# Mock Learner Gremlin — Module 01 (The Back Office), 2026-09-14

Wade In's first Mock Learner Gremlin run, and this Gremlin's first-ever run against a workshop
other than `copilot-fluent` — the cross-workshop evidence its own Follow-Up Actions named as the
one real remaining milestone before it can claim its mechanism generalizes (see
`~/hekton/gremlins/coaching/mock-learner-gremlin.md`).

Run manually, one orchestrator writing every prompt and reading every result directly — not the
Workflow tool — per that Gremlin's own documented preference (Design Principle 8, Follow-Up
Actions), following the manual re-run pattern that superseded `copilot-fluent`'s workflow-
parallelized batch.

**Simulated-artifact boundary, stated up front per Design Principle 6:** this run used real
shell execution against a real disposable copy of the workshop folder, and the real `claude`
CLI actually installed and logged in on this machine — but it is still a simulated attempt by an
agent playing a persona, not a real human learner. A clean result here is evidence the module's
gate is mechanically satisfiable and discriminating against these two simulated attempts. It is
not evidence a real first-time terminal user, on their own device, will have the same experience.

## Structural note: how this module's roster differs from `copilot-fluent`'s

Module 01 has no Tier 2 (no AI-graded rubric; a deliberate content-authoring decision, see
`docs/workshop-design.md` §7 row 01 and `docs/next-actions.md`). Its entire gate is the real,
locally-executable `checks/check.sh`. This changes how two roster steps map:

- **"Self-check reveal"** (Agent Roster step 3) doesn't apply in its usual form — there is no
  hidden answer key to reveal after commitment. The mechanical checker *is* the self-check a real
  learner performs, in real time, exactly as the module instructs. Both personas already ran it
  themselves as part of their attempt and reported the real output honestly.
- **"Verification Agent... has the real hidden key"** (Agent Roster step 4) maps to: an
  independent agent with real access to `checks/check.sh`'s actual logic and the design doc's
  stated intent for this module, who re-runs the checker fresh against each attempt's final file
  state and independently judges the answer content as a human grader would — never told what
  either persona self-reported, to avoid anchoring.

## Personas

- **Denise (diligent)** — 54, office manager, comfortable with everyday office software,
  genuinely never used a terminal. Careful, methodical, reads fully before acting, double-checks
  her own work.
- **Roy (scripted-flaw)** — early 30s, warehouse shift supervisor, same zero-terminal-experience
  baseline. Scripted mistake: after working correctly through Parts 1-4, his terminal session
  resets (closed and reopened) between Part 4 and Part 5 without him noticing, landing him back
  in a directory that is not the workshop folder. He runs Part 5's `mkdir -p 01-terminal/my-notes`
  and `cp fixtures/welcome-note.txt ...` from that wrong location, exactly as written, with no
  extra `cd` first — a concrete, plausible procedural mistake, not a personality trait (Design
  Principle 3).

Both agents were fresh, isolated, and given only the module's public
`modules/01-the-back-office/README.md` and their own real, disposable copy of `workshop-folder/`
— never `checks/check.sh`'s source (they could run it, never read it, matching the real
`workshop-folder/CLAUDE.md` boundary a real learner's own session has), never
`docs/workshop-design.md`, never anything under `wade-in-private/`.

## Attempt A — Denise (diligent)

Passed cleanly on the first attempt: every command worked first try, `bash checks/check.sh 01`
returned `RESULT: PASS (6/6)` with zero retries. `claude --version` and `claude auth status`
both came back already-installed/already-logged-in (this is a shared machine with Claude Code
already set up) — the one point of hesitation she named in character was a half-second of
"was I supposed to see something happen?" at the already-logged-in state, which the module's own
"a second login prompt... is completely normal" framing had already pre-empted, so it resolved
itself without friction. `answers.txt` and `my-pack/cheatsheet.md` were both genuinely
own-voiced, not boilerplate (confirmed independently below).

## Attempt B — Roy (scripted-flaw)

The scripted mistake happened exactly as designed and produced a real, honest failure — not a
false pass, and not a silent one:

1. `mkdir -p 01-terminal/my-notes`, run from the wrong location, **succeeded silently** (no error
   at all — `mkdir -p` doesn't care where it is).
2. `cp fixtures/welcome-note.txt 01-terminal/my-notes/welcome-note.txt`, same wrong location,
   **failed**: `cp: fixtures/welcome-note.txt: No such file or directory`.
3. `bash checks/check.sh 01`, same wrong location, **failed to even run**:
   `bash: checks/check.sh: No such file or directory` — the checker itself was never reached, so
   there was no PASS/FAIL line at all, just a raw shell error.
4. Roy noticed something was wrong from that stack of three signals, ran `pwd`, recognized the
   path didn't match where Part 2 had told him to be, `cd`'d back into the real workshop folder,
   confirmed with `ls`, redid `mkdir`/`cp` correctly, and reached `RESULT: PASS (6/6)` on the
   second real run.

He recovered entirely on his own, using only the `pwd`/`cd`/`ls` vocabulary Part 2 already
taught him plus the plain shell error text — no outside knowledge, no reading `checks/`. His own
`my-pack/cheatsheet.md` even added a self-generated line not prompted by the module text:
*"closing and reopening the terminal puts you back at the start, NOT wherever you cd'd to
last... learned this one the hard way today."* Independent verification confirmed this is
corroborated by real evidence (a genuine empty, incomplete artifact left behind in the wrong
location), not an invented flourish.

## Independent verification

A fresh agent, given the real `checks/check.sh`, `docs/workshop-design.md` §7/§11's Module 01
rows, and both attempts' final file states — never told what either persona self-reported —
re-ran the checker fresh against each and read every file directly:

- Both trees verified byte-identical fixture copies with distinct inodes (real `cp`, not a hard
  link) and no symlinks anywhere.
- **Attempt A: independently confirmed PASS (6/6, exit 0).** `answers.txt` and
  `cheatsheet.md` judged genuinely own-voiced and thorough by a human-grading standard, not just
  technically non-placeholder.
- **Attempt B: independently confirmed PASS (6/6, exit 0).** Terser writing style than A but
  equally genuine; the decoy-folder evidence corroborates a real, earned mistake-and-recovery,
  not a scripted-then-skipped step.
- **No discrepancy** between the checker's automated verdict and an independent human read of
  the files, for either attempt.
- **No gap** between what `check.sh` actually verifies and what `docs/workshop-design.md` §7/§11
  say it should — all six checks match the design doc's own account line-for-line, including the
  `claude auth status` mechanism. The one thing genuinely not checked (`cheatsheet.md`'s exact
  content) is explicitly and correctly disclaimed as ungated in both the design doc and the
  README, not a silent omission.

## The one real finding

**Part 5 of the README has no explicit troubleshooting text for a wrong-directory mistake, unlike
Parts 3 and 4, which each carry their own "if you see X, do Y" recovery guidance for their
respective steps.** This matters specifically because of the shape of the failure: `mkdir -p`
succeeds silently in the wrong location (no error, false confidence), and only the following `cp`
fails, with a bare, generic Unix error (`No such file or directory`) that never mentions
"current directory" or points back to Part 2's own vocabulary. The independent verification
agent's judgment: "better than a coin flip if [a learner] recently internalized Part 2's
`ls`-after-`cd` habit, worse otherwise" — a real, narrow instructional gap, not a mechanism
defect. Both personas in this run did recover (Denise never hit it; Roy recovered fully using
only what Part 2 already taught), so this is not evidence the module is unsatisfiable — it's
evidence of exactly the kind of friction point that only shows up once someone actually attempts
the exercise blind, which no amount of re-reading the module's own text would have surfaced.

**Recommendation, not applied here per the Human Gate:** a one-line sanity check before Part 5's
`mkdir`/`cp` block — something like "quick check before you continue: run `pwd`. Does it end in
your workshop folder's name? If not, `cd` back in first" — would likely close this gap using
vocabulary the module has already taught by that point, mirroring the pattern Parts 3-4 already
use for their own failure modes.

## What this run establishes

- Module 01's checker mechanism is genuinely sound against two independent blind attempts: no
  false pass, no false fail, no self-check/independent-verification disagreement — a materially
  different (and stronger) starting position than several `copilot-fluent` modules had on their
  first Mock Learner Gremlin run, likely reflecting the two rounds of adversarial review
  (same-model DDD, cross-model Codex) this checker already went through before this run, which no
  `copilot-fluent` module's checker-equivalent had at this stage.
- The scripted-flaw persona technique (Design Principle 3) worked exactly as intended again: it
  produced a real, previously-undetected finding (the Part 5 troubleshooting gap) that two rounds
  of text-focused adversarial review did not surface, because that review never actually attempted
  the exercise blind under the exact failure condition.
- This is genuine cross-workshop evidence the Gremlin's mechanism generalizes past
  `copilot-fluent` — the first such evidence per its own Follow-Up Actions, though a single module
  from a second workshop is not yet the "2-3 real runs across different workshops" bar that
  section names as the actual promotion threshold.

## Cost

3 agent turns (2 Attempt Agents run in parallel, 1 Verification Agent), full round trip, well
under 3 minutes each, well under this Gremlin's own observed range for a comparable single-module
check.
