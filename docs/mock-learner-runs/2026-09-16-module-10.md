## Marcus (scripted-flaw) — FAIL 40/43, isolated with precision, root cause confirmed by direct code inspection

**Scripted flaw:** a literal, concrete mistake in Part 2 only - Marcus skimmed the fixtures and believed there were only 6 crew-hours files (the 8th through the 13th), missing that opening night itself (the 14th and 15th) also had files. His literal request named only the 6 dates he believed existed.

**What happened, confirmed at the code level:** the fresh Verification Agent read the actual generated script (`tally_hours.py`) and found its date list hardcoded to `range(8, 14)` - six days, exactly Marcus's flawed belief, with a docstring literally saying "across the six daily fixture files." This silently dropped the two most consequential days in the entire capstone: 2026-09-15 (opening night itself, the true busiest day at 40 hours) and 2026-09-14 (the true lightest day at 9 hours). Every other part of the capstone was done correctly - research, budget, guest merge, and photos/letters all passed cleanly, and the fresh Verification Agent independently reconfirmed the guest-list merge was byte-identical to the correct expected result for both personas. The checker's three failures land exactly and only on the flawed part: `RESULT: FAIL (40/43)`, independently reconfirmed by direct re-run and by the fresh Verification Agent's own from-scratch recomputation of the true 172/40/9 values from the 8 real fixture files.

**A genuinely new nuance for this sweep:** unlike Modules 03 and 08 (where a real Claude Code session quietly self-corrected an ambiguous omission or typo), here the nested session *noticed* the 09-14 and 09-15 files existed but respected Marcus's explicit, stated scope ("six files") rather than overriding his stated belief. This is a meaningful, real distinction: an implicit gap in an otherwise well-specified request tends to get filled in sensibly; an explicit, if wrong, instruction gets followed as given. Both are reasonable product behaviors, but they have opposite implications for scripted-flaw design going forward - see the sweep-wide synthesis.

**Marcus's own hand-check didn't catch it, for a precise reason:** he verified his report's arithmetic against the 6 files he believed existed (14+18+22+26+31+12=123, which does check out internally) - never against the README's actual stated file count. His self-verification was real and honest, just scoped to the same wrong boundary as his original mistake, illustrating the module's own point (verify against the source, not just against internal consistency).
